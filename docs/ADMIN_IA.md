# 管理后台重新规划：菜单 · 字段 · 控件 · 列表

> 依据：当前 `frontend/src/App.tsx` 的 `AdminPage` 与 `components/Admin*.tsx`、后台 API 返回字段、P0 之后的门店隔离规则。
> 标 **【新增】** 的字段/功能需要后端补接口或字段，其余现有 API 已提供。
> 配套：问题与修复阶段见 [ADMIN_FIX_PROMPT.md](ADMIN_FIX_PROMPT.md)；本文是 P1–P3 的界面规格。

## 1. 现状的主要问题

| 问题 | 现状 | 后果 |
|---|---|---|
| 菜单平铺 10 项 | 概览、充值、订单、客户、商品、优惠券、财务、审计、员工、设置并列 | 日常操作（接单、核款）和低频配置（设置、员工）混在一起；"钱包"叫"充值" |
| 订单是"行内一切" | 一行里塞状态、支付、金额、明细、凭证、按钮 | 无法扫读；没有详情、时间线；只能按状态筛选，无搜索、无分页 |
| 商品页三表单叠放 | 分类表单 + 商品表单 + 列表，每行 5 个按钮 | 表单常驻占满页面；三语名称各一行输入框；分类用多选框 |
| 客户表过薄 | 5 列：名称、ID、聊天、订单数、完成数 | 看不到钱包、消费、最近下单，无法运营 |
| 员工行内编辑 | 行内改 Telegram ID / 角色 / 停用，建员工表单常驻 | 误操作风险高；无重置密码、无最近登录 |
| 设置一个大表单 | 币种/时区自由文本，营业、收款、通知、费用全部平铺 | 币种时区可被误改；分组不清 |
| 财务重复 | 日报面板 + 旧区间面板 | 口径分散；缺配送费、服务费 |
| 审计只有分页 | 无筛选、无详情 | 查不到"谁改了什么" |
| 总部 vs 门店不分 | 同一套菜单，总部无门店切换 | 总部账号看不清当前在看哪家店 |

## 2. 角色与可见性

| 角色 | 判定 | 说明 |
|---|---|---|
| 服务员 STAFF | `role=STAFF` | 只处理订单、核款、看本店客户 |
| 门店经理 | `role=MANAGER` 且 `store_id` 非空 | 本店全部运营；目录只读（多店时），可改本店覆盖 |
| 总部 HQ | `role=MANAGER` 且 `store_id` 为空 | 所有门店；改共享目录；门店管理 |
| 财务（后续） | 新增 `HQ_FINANCE` | 只读财务与结算 |

全局顶栏：**门店切换器**（仅总部显示，选"全部门店"或某店；所有列表和统计随之过滤）、语言、通知铃铛（待接单/待核款数）、账号菜单（退出）。

## 3. 新菜单结构

```
工作台                    STAFF · 经理 · 总部
运营
 ├ 订单                   STAFF · 经理 · 总部   （主工作区）
 ├ 钱包充值               STAFF · 经理 · 总部
 └ 客户                   STAFF(只读) · 经理 · 总部
商品
 ├ 菜单管理               经理(本店覆盖) · 总部(共享目录)
 └ 沽清与上下架           STAFF · 经理 · 总部   （快速面板，高频）
营销
 └ 优惠券                 经理 · 总部
财务
 ├ 日报与统计             经理 · 总部（STAFF 仅当班概览）
 └ 结算                   总部 · 财务       （P4，规划里的结算单）
门店                      总部
 └ 门店管理
系统
 ├ 员工与权限             经理 · 总部
 ├ 门店设置               经理 · 总部
 └ 审计日志               经理 · 总部
```

URL 对应：`/admin/orders`、`/admin/wallet`、`/admin/customers`、`/admin/menu`、`/admin/availability`、`/admin/coupons`、`/admin/finance`、`/admin/settlement`、`/admin/stores`、`/admin/staff`、`/admin/settings`、`/admin/audit`。订单详情用抽屉并带 `?order=CODE`，可直链、可刷新。

## 4. 通用控件规范

| 控件 | 规则 |
|---|---|
| **DataTable** | 服务端分页（默认 25，可选 25/50/100）、列头排序、固定首列和操作列、列显示开关、空/加载/失败三态、行点击开抽屉 |
| **Toolbar** | 左：搜索框（支持订单号/房间号/客户名/Telegram）；中：筛选 chips（状态、日期范围、门店）；右：刷新、导出、主按钮。筛选写进 URL |
| **状态 Tab 计数** | 订单页顶部按状态分 Tab，带数量角标；"待核款"用警示色 |
| **Drawer 抽屉** | 详情与编辑都用右侧抽屉（宽 560/720），不跳页；底部固定"取消/保存" |
| **ConfirmDialog** | 取消订单、退款、拒绝凭证、调账、停用员工、下架：必须填原因的用文本域并校验非空；金额类操作显示"将发生什么"摘要 |
| **MoneyInput** | 以币种小数位输入，内部转最小单位整数；右侧显示币种；禁止负数（调账另有正负切换） |
| **LocalizedInput** | 一个字段、三语页签（中/EN/ខ្មែរ）；缺失语言在页签上标红点；英语为回退，缺英语不可保存 |
| **StatusBadge** | 订单状态、支付状态、券状态、门店状态统一颜色与图标（不只靠颜色，带文字） |
| **ImageUpload** | 预览 + 替换 + 删除；限制 5MB、JPEG/PNG/WebP；显示建议尺寸 |
| **DateRange** | 默认今日；快捷：今日/昨日/近7天/本月；按门店时区；显示时区标注 |
| **RowMenu** | 行末"⋯"收纳低频/危险操作；主操作（如"接单"）保持为可见按钮 |
| **批量操作条** | 勾选后底部浮出：批量上下架、批量导出；无批量需求的表不显示勾选框 |

## 5. 各页面规格

### 5.1 工作台
- **KPI 卡（可点击跳转到已筛选的订单列表）**：待接单、待核款、制作中、待送达、超时单【新增】、今日订单数、今日销售额（不含取消）、待审核充值。
- **待办队列**：按"等待最久"排序的前 10 单，显示订单号、房间号、状态、已等待时长，行内放主操作按钮。
- **提示条**：门店暂停接单、员工群未配置、日报投递失败（读取日报投递状态）。

### 5.2 订单（核心页）
**顶部 Tab**：全部 · 待接单 · 待核款 · 制作中 · 待送达 · 已送达 · 已完成 · 已取消（带计数）。

**列表列**

| 列 | 字段 | 说明 |
|---|---|---|
| 订单号 | `public_code` | 点击开抽屉，可复制 |
| 下单时间 | `created_at` | 门店时区；相对时间 + 悬浮显示绝对时间 |
| 房间号 | `room_number` | |
| 客户 | 姓名/Telegram【需订单接口带出】 | 点击跳客户抽屉 |
| 商品摘要 | `items` | 前两项 + "等 N 件" |
| 金额 | `total_minor` | 下方小字：钱包 `wallet_paid_minor` · ABA `external_due_minor` |
| 支付 | `payment_method` + `payment_status` | 徽标 |
| 状态 | `order_status` | 徽标 |
| 门店 | `store_id` | 仅总部且选"全部门店"时显示【需带出门店名】 |
| 操作 | — | 主按钮（随状态变化：接单 / 确认支付 / 出餐 / 已送达 / 完成）+ ⋯ |

**筛选**：订单状态（多选）、支付状态、支付方式、日期范围、门店、有无优惠券【新增】、搜索。

**⋯ 菜单**：查看凭证、上传凭证（经理）、取消订单（必填原因）、退款（经理，必填原因、金额）、复制订单摘要。

**详情抽屉（5 个分区）**
1. **概览**：订单号、状态/支付徽标、下单时间、房间号、客户（含联系入口）、客户语言、门店。
2. **金额明细**：商品小计 → 优惠券名称与优惠 → 配送费 → 服务费 → **订单总额** → 钱包抵扣 → ABA 应付 → 已退款【新增】。
3. **商品**：名称（订单快照）、规格/加料、甜度、单价、数量、行小计。
4. **付款凭证**：图片、提交时间、审核状态；"确认到账 / 拒绝（必填原因）"。无凭证时显示"上传凭证"（经理）。
5. **时间线**：`OrderEvent`（状态变化、操作人、来源后台/群组、原因）。

### 5.3 钱包充值
- **Tab**：待审核 · 待二次审核 · 已入账 · 已驳回 · 已过期/取消。
- **列**：充值单号、客户（姓名/Telegram）、充值金额、实收金额、赠送金额、审批进度（n/N）、状态、提交时间、操作（查看/确认到账/驳回）。
- **详情抽屉**：凭证图片；客户当前余额（本金/赠送/冻结）；实收金额输入（MoneyInput，默认订单金额）；备注；确认/驳回（驳回必填原因）。
- **客户钱包抽屉**（从客户页和这里都能打开）：余额三项、流水表（时间、类型、金额、余额、备注）、**调账**（仅经理：本金/赠送单选、正负金额、必填原因，二次确认）。

### 5.4 客户
**列**：客户（姓名 + @用户名）、Telegram ID、归属门店、语言、订单数、完成数、累计消费【新增】、钱包可用余额【新增】、最近下单【新增】、注册时间、联系（打开 Telegram）。
**筛选**：搜索（姓名/用户名/ID）、门店、语言、有钱包余额、近 30 天未下单【新增】。服务端分页。
**抽屉**：基本资料；订单历史（可点开订单抽屉）；钱包流水；已领优惠券；标签/备注【新增，如"常客""多次取消"】。

### 5.5 菜单管理
**布局**：左栏分类（可拖拽排序，显示商品数，启用开关，"+ 新分类"），右侧商品表。

**商品表列**

| 列 | 字段 |
|---|---|
| ☐ | 批量选择 |
| 图 | `image_key` 缩略图 |
| 名称 | 当前语言名；缺翻译时显示"缺 EN/中/ខ្មែរ"徽标 |
| 分类 | `category_ids`（chips） |
| 价格 | `price_minor`（门店视角显示有效价；与总部价不同时标"已覆盖"） |
| 规格/加料 | 规格组数 / 选项数 |
| 售卖时间 | 窗口摘要（如 08:00–11:00；空=全天） |
| 甜度 | 开/关 |
| 状态 | 上架 / 售罄 / 总部下架 |
| 排序 | `sort_order`（拖拽） |
| 操作 | 编辑 · ⋯（上下架、复制、归档） |

**筛选**：分类、状态、缺翻译、有规格、搜索名称。**批量**：上架/售罄/归档。

**编辑抽屉（页签）**
- **基本**：名称与描述（LocalizedInput 三语页签）、图片、价格（MoneyInput，币种只读取门店币种）、所属分类（多选 chips，可搜索）、甜度开关、排序、上架开关。
- **规格与加料**：规格组列表（名称三语、类型 SPEC 单选 / ADDON 多选、必选、最多选、启用）；每组下选项表（名称三语、加价、默认、启用）；组内可拖拽排序。
- **售卖时间**：时间窗行（开始、结束，跨午夜提示）；"全天"开关。
- **门店覆盖**（门店视角出现）：价格、上下架、排序、售卖时间；每项旁显示"继承总部：¥X"和"恢复继承"按钮【P2 新增接口】。
- **历史**：该商品的审计记录。

**权限呈现**：多店模式下，门店经理看到共享字段为只读（灰色并提示"由总部维护"），只有"门店覆盖"页签可编辑。

### 5.6 沽清与上下架（高频快速面板）
单列表：商品名、分类、当前状态大开关（可售 / 今日售罄）、"恢复时间"（可选，次日 00:00 自动恢复【新增】）。给服务员用，不需要打开编辑抽屉。

### 5.7 优惠券
**列**：名称、类型（折扣/满减）、规则摘要（"满 10 减 2"/"8 折，封顶 3"）、发放方式（公开/私有）、有效期、领取数/总量、已使用数【新增】、状态（草稿/上线/暂停/已过期）、操作。
**操作**：发布、上线/下线、复制公开链接、分享、生成私有链接（私有券：展示已发放/已领取）、作废【新增】、复制为新券【新增】。
**新建（分步抽屉）**：① 基本（名称、说明、币种）→ ② 规则（类型；折扣：百分比 + 封顶；满减：金额；最低消费）→ ③ 发放（公开/私有；每人限领、总量；起止时间，显示时区）→ ④ 预览（用示例订单试算优惠，核对后保存草稿）。
**详情**：领取/使用明细表（客户、领取时间、使用订单号）。

### 5.8 日报与统计
- **顶部**：日期范围、门店（总部）、币种。
- **KPI 分组**：
  - 销售：订单数、取消数、**订单销售额**；拆解行：商品小计 − 优惠 + 配送费 + 服务费 = 销售额（必须对得上）。
  - 收款：ABA 订单收款、钱包扣款、充值入账、**现金流入**、待核验。
  - 退款【新增】：退款笔数/金额。
- **明细表（按日）**：日期、订单数、销售额、优惠、ABA、钱包、充值、取消。
- **日报投递**：目标群、计划时间、投递状态、"预览文本"、"立即发送"（经理）。
- **导出** CSV（受门店隔离）。

### 5.9 门店管理（总部）
**列**：编码、名称、加盟商、状态（营业/暂停/关闭）、接单中、币种/时区、员工群是否已配置、抽成（比例 + 固定）、结算周期、今日订单数。
**操作**：新建/编辑、暂停/恢复、复制顾客入口深链与二维码（`start=store_{code}`）、切换到该店视角。
**抽屉**：基本、经营参数、收款、通知群、结算（抽成、周期）。

### 5.10 员工与权限
**列**：账号、角色、归属门店（总部可见；空=总部）、Telegram ID、状态、最近登录【新增】、操作。
**操作**：新建（抽屉，非常驻表单）、编辑（角色、Telegram ID）、重置密码（生成并要求对方改，12+ 位）、停用/启用（自己不可停用）。每个危险操作二次确认并写审计。
**新建字段**：登录名、初始密码（强度提示）、角色、归属门店（总部可选，门店经理固定本店且不可见）、Telegram ID（可选，绑定后才能在群里操作）。

### 5.11 门店设置（页签，只改当前门店）
| 页签 | 字段 / 控件 |
|---|---|
| **营业** | 接单开关；营业时间段（可多段，跨午夜提示）；起送金额（MoneyInput）；配送费；服务费 |
| **收款** | 币种（创建后只读，改动需总部并二次确认）；ABA 二维码（ImageUpload）；支付链接（https 校验） |
| **通知** | 员工群 ID（附"如何获取"说明、**发送测试消息**按钮【新增】）；群语言；日报发送时间 |
| **区域** | 时区（下拉选 IANA，附当前本地时间预览）；房间号规则（格式/楼栋范围）【新增】 |
保存按页签独立提交，显示"未保存更改"提示，并在审计中记录变更前后值。

### 5.12 审计日志
**筛选**：时间范围、操作人、对象类型（订单/商品/员工/设置/钱包/优惠券）、动作、来源（后台/群组）、搜索订单号。
**列**：时间、操作人（+Telegram）、来源、对象（点击跳转）、动作、状态变化 / 原因。
**行展开**：详情 JSON 的前后值对比。导出 CSV。门店经理只见本店；总部级操作（目录）只有总部可见（P0 规则）。

## 7. 落地顺序（对应 ADMIN_FIX_PROMPT 阶段）

1. **P1**：路由化骨架 + 通用组件（DataTable、Toolbar、Drawer、ConfirmDialog、MoneyInput、LocalizedInput、StatusBadge）+ 新菜单分组；合并财务页。
2. **P3 前移到 P1 之后**：订单工作台（最影响日常效率）。
3. **P2**：菜单管理重做 + 门店覆盖 + 门店管理。
4. 客户/钱包抽屉、员工抽屉、设置页签、审计筛选。
5. 沽清面板、工作台待办队列。
6. 结算（P4）。

后端需要新增或补字段的汇总：订单列表带客户名与门店名、服务端分页与搜索（订单/客户）、客户累计消费与最近下单、员工最近登录、优惠券使用数与作废、门店覆盖接口、沽清自动恢复时间、发送测试消息接口、房间号规则、订单退款金额。

# 附录 A：接口契约（新增/变更）

> 原则：旧接口保持不动（向后兼容），新能力走新路径或新增可选字段；所有新接口走 `get_current_staff` / `get_current_manager` 并复用 `store_context` 的隔离函数（订单、客户用 `store_scope_clause`；员工、审计用 `strict_store_clause`）；所有写操作写 `AuditLog` 且带 `store_id`。

## A.1 统一分页信封
```json
{ "items": [...], "total": 123, "limit": 25, "offset": 0 }
```
查询参数：`limit`(1–100，默认 25)、`offset`(≥0)、`sort`(白名单字段，前缀 `-` 为降序)、`q`(搜索)。排序字段必须白名单，不得拼接用户输入进 SQL。

## A.2 订单
| 接口 | 说明 |
|---|---|
| `GET /api/v1/admin/orders/search` | 新增。参数：`status`(可多值)、`payment_status`、`payment_method`、`from`/`to`(门店时区日期)、`store`(仅总部，门店码)、`has_coupon`、`q`(订单号/房间号/客户名/Telegram ID，ILIKE)。返回信封，`items` 每项含现有字段 + `customer:{id,display_name,username,telegram_user_id}` + `store:{id,code,name}` + `item_count` + `items_preview`(前 2 项名称) + `refunded_minor` |
| `GET /api/v1/admin/orders/counts` | 新增。返回各 `order_status` 及"待核款"(`payment_status=PROOF_SUBMITTED`)的数量，供 Tab 角标；同样按门店隔离，可带 `store` |
| `GET /api/v1/admin/orders/{id}` | 新增详情：订单全字段、金额明细、`items`(含 `options_json`)、`proof`(状态/时间，无图片本体)、`events`(OrderEvent 列表：event、actor、from/to、created_at) |
| 现有 `GET /api/v1/admin/orders` | 保留（标记 deprecated），不改返回结构 |
| 现有 status / payment-review / refund / payment-proof | 不变 |

## A.3 客户
`GET /api/v1/admin/customers/search`：参数 `q`、`store`、`language`、`has_balance`、`inactive_days`、分页。每项新增 `store`、`preferred_language`、`total_spent_minor`(已完成订单合计，按币种分组取主币种)、`last_order_at`、`wallet:{available_minor,frozen_minor,currency}`。钱包取数走 `wallet_service.get_summary`，注意 N+1：批量查询。
`GET /api/v1/admin/customers/{id}`：详情含订单历史(最近 20)、已领优惠券、标签/备注(【新增表 customer_notes，可后置】)。
旧 `GET /admin/customers` 保留。

## A.4 菜单与门店覆盖（P2）
| 接口 | 说明 |
|---|---|
| `GET /api/v1/admin/menu` | 管理视角菜单：分类 + 商品，商品含 `effective:{price_minor,available,sort_order,sale_windows}` 与 `override:{...}|null`、`missing_locales:[..]`；门店账号按自己门店解析，总部可 `?store=` |
| `PUT /api/v1/admin/stores/{store_id}/products/{product_id}/override` | 设置覆盖，字段均可为 null 表示继承；门店经理只能操作本店 |
| `DELETE` 同路径 | 恢复继承 |
| `PATCH /api/v1/admin/products/{id}/availability` | 沽清快速开关：`{available: bool, restore_at?: ISO}`；门店经理/服务员作用于**本店覆盖**，不改共享目录；总部作用于共享目录 |
| `PUT /api/v1/admin/categories/order`、`PUT /api/v1/admin/products/order` | 批量排序：`[{id, sort_order}]`，总部 |

## A.5 门店管理（总部）
`GET/POST /api/v1/admin/stores`、`PATCH /api/v1/admin/stores/{id}`（名称三语、状态、币种、时区、抽成、结算周期、merchant）；`GET /api/v1/admin/stores/{id}/entry-link`（返回 `https://t.me/<BOT>?startapp=store_<code>` 与二维码 PNG/SVG）。门店经理不可访问（403）。币种创建后修改需 `confirm_currency_change=true` 并写审计。

## A.6 员工
`GET /api/v1/admin/staff` 增加 `store`(名称)、`last_login_at`【新增列 staff.last_login_at，登录成功时更新】。
`POST /api/v1/admin/staff/{id}/reset-password`：生成一次性临时密码返回一次、`must_change_password=true`（新列）；写审计；不得记录明文。
登录后若 `must_change_password` 强制改密页。

## A.7 其他
- 门店设置：`POST /api/v1/admin/settings/test-notification`（向员工群发测试消息，返回成功/失败原因）。
- 审计：`GET /api/v1/admin/audit-logs` 增加参数 `from`/`to`/`actor`/`entity_type`/`action`/`source`/`q`；仍用 `strict_store_clause`。
- 统计：`GET /api/v1/admin/analytics/` 增加 `daily:[{date,orders,sales_minor,discount_minor,aba_minor,wallet_minor,recharge_minor,cancelled}]` 与退款汇总；沿用现有币种分桶。
- 导出：`GET /api/v1/admin/orders/export.csv`、`customers/export.csv`（与列表同一筛选与隔离；CSV 注入防护：以 `= + - @` 开头的单元格前加 `'`；单次上限 10,000 行）。

# 附录 B：前端结构与组件契约

```
frontend/src/admin/
  AdminApp.tsx            # 路由表 + 鉴权守卫（未登录 → /admin/login）
  layout/AdminLayout.tsx  # 侧栏(分组导航) + 顶栏(门店切换器/语言/铃铛/账号)
  layout/nav.ts           # 导航配置：{ key, path, labelKey, roles, hqOnly }
  hooks/useAdminSession.ts, useStoreScope.ts, useQueryState.ts(筛选↔URL)
  components/DataTable.tsx, Toolbar.tsx, Drawer.tsx, ConfirmDialog.tsx,
             MoneyInput.tsx, LocalizedInput.tsx, StatusBadge.tsx, EmptyState.tsx
  pages/Dashboard, Orders, Wallet, Customers, Menu, Availability,
        Coupons, Finance, Stores, Staff, Settings, Audit
  api/ (按资源拆分的 typed client；类型与后端响应一一对应，禁止 any)
```
- 路由用 react-router 嵌套路由；导航项由 `nav.ts` + 当前 role/store 过滤，**前端隐藏只是体验，权限以后端为准**。
- `DataTable<T>`：props 为 `columns`、`fetchPage(params)`、`rowKey`、`onRowClick`、`selectable?`；内部管理 loading/error/empty，不自己拼 URL。
- `MoneyInput`：`value`(最小单位整数 | null)、`currency`、`onChange`；用 `Intl.NumberFormat(...).formatToParts` 取小数位，**不得用浮点乘法**（用字符串分割 + 整数运算）。KHR 等无小数币种按 0 位处理。
- `LocalizedInput`：`value: {en?,'zh-CN'?,km?}`，`requireEnglish`，页签红点提示缺失。
- 所有新增文案同步写入 `docs/ui/locales.json` 三语；新增 `scripts/check-i18n` 校验三语 key 一致且代码引用的 key 都存在，并接入 `npm run lint` 或 CI。
- 无障碍：表格有 caption/scope，抽屉焦点陷阱 + Esc 关闭，按钮有可读名称，状态不只靠颜色。
- 响应式：≥1024 侧栏常驻；<1024 抽屉式导航；表格在窄屏降级为卡片列表（订单页必须可用，服务员常用手机）。
- 高棉语：检查 Khmer 字体栈、表头断行、按钮宽度不溢出。

# 附录 C：验收标准

## 功能
1. 按角色看到的菜单符合第 3 节；服务员看不到财务/营销/系统；门店经理看不到门店管理；总部有门店切换器。
2. 订单页：Tab 计数正确；搜索订单号/房间号/客户名/Telegram ID 命中；日期、状态、支付方式筛选组合正确；翻页不丢筛选；刷新页面状态保持（URL）。
3. 订单抽屉：金额明细满足 `小计 − 优惠 + 配送费 + 服务费 = 总额`；`总额 − 钱包抵扣 = ABA 应付`；时间线包含所有 OrderEvent。
4. 主操作按钮仅在合法状态出现；非法转换后端 409，前端展示本地化提示；取消/拒绝/退款/调账均强制原因；重复点击不产生重复请求（按钮 busy）。
5. 菜单页：门店经理（多店）对共享字段只读；覆盖保存后顾客菜单价与下单价一致；"恢复继承"生效；沽清只影响本店。
6. 设置页签独立保存；币种变更需二次确认并写审计；测试消息按钮能报告失败原因。
7. 员工：新建/编辑在抽屉；重置密码后对方首次登录被强制改密；不能停用自己。
8. 审计：所有筛选可用；门店经理看不到总部级与他店记录。
9. 财务：日报与区间合并为一页；各口径与 `docs/FINANCE_METRICS.md` 一致；CSV 导出与屏幕筛选一致。
10. 三语完整，无裸 key；高棉语无溢出。

## 安全（每条都要有自动化用例）
- 所有新接口：跨店访问他店资源 → 404；STAFF 调经理接口 → 403；门店经理调总部接口 → 403。
- 搜索与排序参数不可注入（白名单 + 参数化）。
- CSV 导出防公式注入；导出同样受隔离与限流。
- 重置密码接口不回显明文于日志/审计；临时密码仅返回一次。
- 新列表接口无 N+1：对 25 行分页的订单/客户列表，SQL 语句数不随行数增长（用 SQLAlchemy 事件计数断言）。

## 质量
- `tsc --noEmit`、lint、vitest 全绿；关键组件（MoneyInput 取整/小数位、LocalizedInput、DataTable 三态）有单测。
- Playwright 冒烟：登录 → 订单 Tab 切换 → 搜索 → 打开抽屉 → 接单 → 确认支付（用种子数据）；三语切换；窄屏订单页。
- 后端 `cross_store_security_test.py` 扩充并保持通过；迁移可在空库与已有数据库上执行（含 downgrade 说明）。
